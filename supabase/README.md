# Инструкции по базе данных Supabase

В этой директории (`supabase/migrations/`) хранятся SQL-миграции базы данных. Каждая миграция — это шаг развития нашей базы. Они нумеруются по порядку (`001`, `002` и т.д.), чтобы мы могли последовательно применять изменения архитектуры, сохраняя полную хронологию проекта.

## Хронология Миграций

### `001_initial_schema.sql`
**Цель:** Инициализация ядра системы.
**Создает таблицы:** 
- `orders` (Заказы агентства)
- `transactions` (Финансы: доходы и расходы)
- `leads` (Лиды для CRM доски)

### `002_wishlist.sql`
**Цель:** Внедрение списка желаний (планируемые покупки компании).
**Создает таблицы:** 
- `wishlist` (Карточки с ценами и статусами)

### `003_telegram.sql`
**Цель:** Подготовка инфраструктуры для уведомлений в Telegram.
**Создает таблицы:** 
- `telegram_settings` (Хранение токенов ботов и Chat ID)

### `004_currency_rates.sql`
**Цель:** Управление валютными курсами.
**Создает таблицы:** 
- `currency_rates` (Для переопределения курсов ЦБ ручными настройками)

### `005_erp_update.sql` (Глобальное обновление - Фаза 5)
**Цель:** Масштабирование MVP до полноценной ERP-системы.
**Что добавляет:**
1. **Сотрудники**: Создает таблицу `employees` для хранения команды.
2. **Планировщик (Kanban)**: Создает таблицу `tasks`, для привязки этапов производства к Заказам.
3. **Обновление Заказов**: Добавляет новые колонки `executor_id`, `finder_id` и `notes` в существующую таблицу `orders` (через `ALTER TABLE`).

## 🛠 Как применить эти миграции

Если вы разворачиваете проект с нуля, выполните скрипты по очереди (от 001 до 005):

1. Откройте ваш проект в панели управления [Supabase SQL Editor](https://supabase.com/dashboard/project/_/sql/new).
2. Создайте новый запрос (**New query**).
3. Скопируйте всё содержимое нужного файла миграции и вставьте в редактор.
4. Нажмите кнопку **Run** (Запустить).
   - *Важно: Всегда выбирайте "Run without RLS", так как в MVP мы используем кастомную ролевую модель на клиенте.*
5. Убедитесь, что нет ошибок, и переходите к следующему файлу.
