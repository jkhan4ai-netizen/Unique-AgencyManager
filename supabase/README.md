# Инструкции по базе данных Supabase (Unique Agency Manager)

В этой директории (`supabase/migrations/`) хранятся SQL-миграции базы данных. Они нумеруются по порядку (`001`, `002` и т.д.), чтобы сохранять правильную хронологию и последовательно применять изменения архитектуры.

## 📜 Хронология Миграций

### `001_initial_schema.sql`
**Цель:** Базовое ядро приложения.
**Таблицы:** 
- `orders` (Список проектов/заказов)
- `transactions` (Доходы и расходы)
- `leads` (Канбан CRM)

### `002_wishlist.sql`
**Цель:** Резерв таблиц для модуля "Список желаний".
**Таблицы:** `wishlist`

### `003_telegram.sql`
**Цель:** Резерв таблиц для хранения настроек Telegram-бота и уведомлений.
**Таблицы:** `telegram_settings`

### `004_currency_rates.sql`
**Цель:** Хранение курсов валют непосредственно в базе данных для ручной корректировки.
**Таблицы:** `currency_rates`

### `005_erp_update.sql` (Глобальное обновление Фазы 5)
**Цель:** Превращение MVP в полноценную ERP-систему с назначением задач.
**Что добавляет:**
1. **Сотрудники**: Создает таблицу `employees` для хранения списка команды.
2. **Планировщик (Kanban)**: Создает таблицу `tasks`, которая хранит задачи (Съёмки, Монтаж) с привязкой к Заказам.
3. **Модернизация Заказов**: Добавляет новые колонки `executor_id`, `finder_id` и `notes` в таблицу `orders` для назначения людей и хранения заметок.

## 🛠 Пошаговая инструкция по применению миграций

Чтобы развернуть чистую базу данных на Supabase с нуля:

1. Откройте проект в панели [Supabase](https://supabase.com/dashboard/).
2. Перейдите в раздел **SQL Editor**.
3. Создайте новый скрипт (New query).
4. Скопируйте и выполните содержимое файлов строго по порядку (с 001 до 005). 
   - Вы можете создать один большой скрипт, скопировав все файлы по очереди в одно окно.
5. При выполнении всегда выбирайте **Run without RLS**, так как наше MVP работает с открытым доступом по Anon Key.
